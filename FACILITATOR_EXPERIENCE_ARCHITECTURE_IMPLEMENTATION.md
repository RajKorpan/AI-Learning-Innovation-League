# Facilitator Experience Architecture Implementation

This revision rebuilds the facilitator experience around the requested live-facilitation architecture.

## Shared system
- Main session reading width capped at 1060px; explanatory prose generally capped around 760px.
- Major session sections use large vertical spacing and subtle dividers rather than card stacks.
- Cards are limited to high-value support panels, quick checks, planner shell, and landing-page session access.
- One quiet color system is used; stage emphasis and warnings/actions receive stronger treatment.
- Desktop session pages include a compact sticky utility bar with session identity, 45/90 toggle, student-stage link, and print action.
- Mobile simplifies the sticky utility and keeps the stage journey horizontally scrollable.

## Landing page
- Spacious hero with four compact quick facts and two actions.
- What students gain / facilitator Do-Avoid remains the conceptual foundation.
- Club planner is constrained to ~900px and Step 6 is labeled Review.
- Generic During-session guidance reduced to one sentence.
- Session resources appear once in five consistent 01–05 cards with Open guide →, Print plan, Student slides.
- Support remains visually secondary.

## Session pages
All five pages now use exactly: Session hero → Before the session → Facilitate → Quick check → Next session.
- Removed Before/While mode switch.
- Removed guided micro-step screens, Back/Next controls, progress meters, and duplicate output screen.
- Before the session is a two-column Prepare / Watch-for + prompts layout.
- Facilitate is a single vertically readable agenda.
- 45/90 changes timing only: activity names, wording, links, outputs, and order are a single shared agenda.
- Quick check contains only readiness questions and next-session navigation follows below.

## Stage-specific requirements
- Empathize reinforces evidence vs. guess, neutral questions, and avoiding premature solutions.
- Define keeps narrowing, direct evidence, best-guess language, and learner-action goals.
- Ideate visibly requires at least one genuinely low-tech/off-screen idea and explains the two ways AI can contribute.
- Prototype renames the AI activity to Build and define AI’s role and presents product-facing vs build-support AI as equal pathways.
- Test + Share has one hero callout: Share progress, not polish; the agenda has Test + revise and Share mode labels without changing the activity sequence.

## Print
All five printable guides were synchronized to the same single activity sequence. Their 45/90 controls change timing only.
