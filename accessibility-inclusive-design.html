Accessibility and Inclusive Design

Design the club and the tools for varied learners.

Accessibility should shape the project from the beginning rather than being added after the prototype is finished.

Reading and language

Use plain language, define terms, provide examples, allow audio or visual explanations, and support multilingual learners.

Visual access

Use readable contrast, scalable text, descriptive labels, and information that does not depend on color alone.

Keyboard and assistive technology

Ensure controls can be reached by keyboard and content is compatible with screen readers where possible.

Cognitive accessibility

Break tasks into steps, reduce unnecessary complexity, show progress, and provide predictable interaction patterns.

Participation options

Offer speaking, writing, drawing, building, testing, documenting, and presenting roles.

Technology alternatives

Provide low-bandwidth, shared-device, printed, storyboard, and advisor-mediated options.

Student accessibility review

  1. Identify who may have difficulty using the tool.
  2. Review language, layout, navigation, and feedback.
  3. Test with more than one type of learner when possible.
  4. Provide an alternative way to complete the interaction.
  5. Record limitations that cannot yet be resolved.
Accessibility testing prompts

Ask more than “Was it easy?”

  • Could the user understand the instructions without additional explanation?
  • Could the user navigate using the available input method?
  • Was the language appropriate for the learner?
  • Did feedback remain respectful and understandable?
  • Could the same learning goal be reached in another format?
  • What barrier appeared, and how could the design reduce it?
